# Final Exam Project (30 Points): Kenya Hospitality & Airbnb Guest Intelligence System

## 1. Project Overview & Connected Pipeline
You are a data analyst and want to make an Airbnb property App in Kenya that can collect visitor data to package and sell as market insights to local Kenyan hotels and hospitality businesses.

This project follows a **connected 3-stage data pipeline** built entirely inside **Posit Cloud** (R Shiny + SQLite) and **Microsoft Excel**:
1. **Part A (Collection):** Guests submit their details through an **R Shiny web form** on Posit Cloud, and you export the collected entries to CSV.
2. **Part B (Cleaning):** You take the raw CSV exported from Part A into **Excel** to standardize messy free-text entries, remove duplicate test runs, and summarize visitor patterns.
3. **Part C (Database & SQL):** Your R Shiny form writes submissions directly to a local **SQLite database** inside Posit Cloud, where you run **SQL queries** to generate business reports for hotel clients.

## 4. Exam Instructions & Grading Rubric (30 Points Total)

### Part A: Data Fundamentals & R Shiny Form on Posit Cloud (12 Points)
Build an interactive visitor check-in form in `app.R` on Posit Cloud using the **5 required guest inputs**.

* **Required Form Inputs (4 pts):**
  Design a clean UI collecting exactly these five fields:
  1. `id` — Guest / Booking ID (Text or Numeric input, e.g., `KE-101`)
  2. `name` — Guest Full Name (Text input)
  3. `country` — Country of Residence / Travelling From (Text input—*use text input so realistic typos/variations occur for Part B cleaning*)
  4. `citizenship` — Guest Citizenship / Nationality (Text input)
  5. `length_of_stay` — Length of Stay in Nights (Numeric input)
  6. `most_preferred_amenity` — 'wifi', 'pool', 'balcony/verandah' (Text input)
* **Server Logic, Data Entry & CSV Export (5 pts):**
  * Add a **Submit** button with input validation (prevent empty `id` or `name`, block `length_of_stay <= 0`, require at least one checkbox to be selected in most_preferred_amenity (!is.null(input$most_preferred_amenity)), and collapses multiple checked boxes into a single comma-separated text string (e.g., paste(input$most_preferred_amenity, collapse = ", ")) before saving to CSV or SQLite).
  * Display all submitted entries in a live `DT::datatable()` preview inside the app.
  * Include a **Download CSV (`downloadHandler`)** button that exports all recorded entries as `raw_guest_entries.csv`.
  * **Data Generation Requirement:** Submit **at least 20 realistic visitor entries** through your running app (intentionally include a few realistic messy entries—such as `"kenya"`, `"KENYA "`, `"usa"`, `"U.S.A."`, extra spaces in names, and 2 duplicate entries—so you have real anomalies to clean in Part B), then click **Download CSV**.
* **Data Fundamentals & Hotel Pitch (3 pts):**
  * Include a brief written summary (inside the app UI or a `readme.md` file) identifying the data type of each of the 5 variables (**Nominal, Ordinal, Discrete, Continuous**) and explaining how a Kenyan hotel or resort can use **`country`**, **`citizenship`**, and **`length_of_stay`** together to design targeted packages.

### Part B: Excel Data Cleaning on Part A Exports (8 Points)
Open the `raw_guest_entries.csv` file you exported from your Part A Shiny app in **Microsoft Excel** and save your cleaned workbook as `cleaned_guest_entries.xlsx`.

* **Text & Formatting Standardization (3 pts):**
  * Remove leading/trailing spaces and fix inconsistent capitalization across `name`, `country`, and `citizenship` using `TRIM()` and `PROPER()` (and `UPPER()` where appropriate, e.g., `"usa"` / `"U.S.A."` → `"USA"`, `"kenya "` → `"Kenya"`).
  * Ensure `id` follows a consistent uppercase format and `length_of_stay` is formatted as a whole number (`0` decimals).
* **Deduplication & Missing Value Audit (3 pts):**
  * Use **Data → Remove Duplicates** (checking `id` and `name`) to eliminate repeated form submissions.
  * Check for any blank cells; replace missing text fields with `"Not Specified"` and impute the median `length_of_stay` if any numeric value is missing.
  * Add a **"Cleaning Log"** tab documenting the exact count of rows exported from Part A, duplicates removed, and standardization rules applied.
* **Hospitality Summary Pivot Table (2 pts):**
  * Create a **Pivot Table** on a separate tab showing **Total Guests (Count of ID)** and **Average Length of Stay (Nights)** grouped by **Country of Residence** and **Citizenship**.

### Part C: SQLite Backend & SQL Queries in Posit Cloud (10 Points)
Connect your Part A R Shiny app directly to a local **SQLite database** (`kenya_hospitality.sqlite`) inside Posit Cloud so all visitor entries persist automatically, then analyze the stored table using SQL.

* **SQLite Database & Table Setup (3 pts):**
  * Configure `app.R` using `DBI` and `RSQLite` so that `kenya_hospitality.sqlite` is created automatically in your Posit Cloud project with the following schema:
    ```sql
    CREATE TABLE IF NOT EXISTS guest_submissions (
      id TEXT,
      name TEXT,
      country TEXT,
      citizenship TEXT,
      length_of_stay INTEGER
    );
    ```
* **Live R Shiny \(\leftrightarrow\) SQLite Integration (4 pts):**
  * Update your **Submit** button so each new entry is saved directly into `guest_submissions` via `dbWriteTable(..., append = TRUE)` (or `dbExecute()`).
  * Load the live preview table and the **Download CSV** button directly from SQLite using `dbReadTable(con, "guest_submissions")`.
* **SQL Analytical Queries (`sql_analysis.R`) (3 pts):**
  * Write and execute **3 SQL queries** in `sql_analysis.R` using `dbGetQuery()` to extract commercial insights for Kenyan hotel buyers:
    1. **Market Breakdown:** Count total guests and calculate average `length_of_stay` grouped by `country`.
    2. **Long-Stay International Guests:** Filter visitors whose `citizenship` is not `'Kenya'` and who stayed `>= 5` nights, ordered from longest to shortest stay.
    3. **Domestic vs. Diaspora Comparison:** Find guests living abroad (`country != 'Kenya'`) who hold `'Kenya'` `citizenship` (returning Kenyan diaspora).
